راهنمای قرار دادن فایل‌های دانلود روی گیت‌هاب (BEE-VPN)
=======================================================

هدف: صفحهٔ Releases ریپازیتوری شما دقیقاً مثل صفحهٔ Releases پروژهٔ اصلی
(BEEHIVE-GUARD اثر CFG.IR در تگ v3.2.0) شود؛ یعنی:

    https://github.com/CFGIR200/BEE-VPN/releases/tag/v3.2.0
    ├─ BEE-VPN-3.2.0-arm64-v8a.apk          (اکثر گوشی‌ها)
    ├─ BEE-VPN-3.2.0-armeabi-v7a.apk        (گوشی‌های ۳۲بیتی)
    ├─ BEE-VPN-3.2.0-x86_64-emulator.apk    (شبیه‌ساز)
    ├─ BEE-VPN-3.2.0-universal.apk          (همهٔ معماری‌ها)
    └─ SHA256SUMS.txt

چرا Releases؟ چون گیت‌هاب اجازه نمی‌دهد فایل بزرگ‌تر از ۱۰۰ مگابایت داخل خود
ریپازیتوری commit شود (universal.app سنگین‌تر از آن است)، ولی فایل‌های Release
تا ۲ گیگابایت پشتیبانی می‌شوند — همان روشی که پروژهٔ اصلی هم استفاده می‌کند.
ضمناً آپدیت‌یاب داخل برنامه هم آدرس releases/latest همین ریپو را چک می‌کند.

چهار فایل APK نسخهٔ 3.2.0 همین حالا بیلد و امضا شده و کنار همین راهنما در
پوشهٔ apk/ قرار دارد — یعنی «فایل‌های دانلود» آماده‌اند؛ فقط باید روی گیت‌هاب
منتشر شوند. سه مسیر دارید:

──────────────────────────────────────────────────────────────────────────────
مسیر الف) من خودم همه‌چیز را انجام دهم  ← سریع‌ترین راه
──────────────────────────────────────────────────────────────────────────────
یک توکن گیت‌هاب بسازید و در همین چت برای من بفرستید:

  ۱. در گیت‌هاب: Settings ← Developer settings ← Personal access tokens
     ← Tokens (classic) ← Generate new token (classic)
  ۲. فقط تیک «repo» را بزنید و توکن را Generate کنید (ghp_...)
  ۳. توکن را همین‌جا بفرستید.

من با همان اسکریپت beevpn_github.sh (که داخل سورس گذاشته‌ام) ریپو را می‌سازم،
سورس را push می‌کنم، تگ v3.2.0 را می‌زنم و ۴ فایل APK را روی Releases منتشر
می‌کنم و لینک نهایی را می‌دهم.
⚠️ بعد از اتمام کار، از صفحهٔ همان توکن، دکمهٔ Delete/Revoke را بزنید.

──────────────────────────────────────────────────────────────────────────────
مسیر ب) خودتان با «یک دستور» انجام دهید (لینوکس / مک / ویندوز Git-Bash)
──────────────────────────────────────────────────────────────────────────────
پوشهٔ سورس BEE-VPN و پوشهٔ apk کنار هم باشند، بعد:

    GH_TOKEN=ghp_xxxxxxxxxxxx ./beevpn_github.sh

همین یک دستور به‌ترتیب: ریپو را می‌سازد ← سورس را push می‌کند ← تگ v3.2.0 را
می‌زند ← Release را می‌سازد ← هر ۴ APK و SHA256SUMS.txt را آپلود می‌کند.
(اگر ریپو یا Release از قبل موجود باشد، به‌جای خطا ادامه می‌دهد و فایل‌ها را
جایگزین می‌کند.)

──────────────────────────────────────────────────────────────────────────────
مسیر ج) بدون هیچ ابزار و توکنی، فقط با مرورگر / GitHub Desktop
──────────────────────────────────────────────────────────────────────────────
۱) ساخت ریپو و push سورس:
   - سورس کامل را از بسته‌های تحویلی سرهم کنید (طبق README-FA.txt).
   - github.com را باز کنید ← دکمهٔ + ← New repository ← نام BEE-VPN ← Create.
   - با برنامهٔ رایگان GitHub Desktop: File ← Add local repository… پوشهٔ
     BEE-VPN را انتخاب کنید ← Publish repository.
۲) انتشار فایل‌های دانلود:
   - صفحهٔ ریپو ← Releases ← Draft a new release
   - در قسمت tag بنویسید v3.2.0 و «+ Create new tag on publish» را بزنید
   - عنوان: BEE-VPN 3.2.0
   - ۴ فایل APK و SHA256SUMS.txt را از پوشهٔ apk/ بکشید و رها کنید
   - متن توضیحات را از دلخواه بنویسید (متن پیشنهادی داخل اسکریپت هست)
   - دکمهٔ Publish release

──────────────────────────────────────────────────────────────────────────────
ثبت Secrets (برای بیلدهای خودکار بعدی — یک‌بار برای همیشه)
──────────────────────────────────────────────────────────────────────────────
تا گیت‌هاب بتواند APK امضاشده بسازد، ۴ Secret لازم است (صفحهٔ ریپو ← Settings
← Secrets and variables ← Actions ← New repository secret):

    AETHERY_KEYSTORE_BASE64    = محتوای Base64 فایل beevpn-release.jks
    AETHERY_KEYSTORE_PASSWORD  = رمز keystore
    AETHERY_KEY_ALIAS          = beevpn
    AETHERY_KEY_PASSWORD       = رمز کلید

دو مقدار رمز داخل فایل keystore.env کنار همین فایل‌ها آمده است.
ساخت Base64 در لینوکس/مک:
    base64 -w0 beevpn-release.jks > jks.b64
در ویندوز (cmd):
    certutil -encode beevpn-release.jks jks.b64
(محتوای بین BEGIN/END در jks.b64 را در Secret بگذارید؛ بدون خطوط اضافه.)

Secret پنجم یعنی BEE_IDENTITY_RELAY_HMAC اختیاری است؛ اگر خالی باشد فقط
قابلیت Identity از طریق relay غیرفعال می‌ماند و بیلد سالم انجام می‌شود.

──────────────────────────────────────────────────────────────────────────────
از این به بعد (نسخه‌های بعدی) — کاملاً خودکار
──────────────────────────────────────────────────────────────────────────────
ورک‌فلو جدید release.yml به سورس اضافه شده: هر وقت تگی با شکل v* پوش کنید
(مثلاً برای نسخهٔ بعدی):

    git tag v3.3.0
    git push origin v3.3.0

گیت‌هاب خودش سورس را بیلد می‌کند، APKها را امضا می‌کند، نام‌گذاری می‌کند
(BEE-VPN-3.3.0-*.apk) و روی همان تگ Release منتشر می‌کند — بدون هیچ کار دستی.

──────────────────────────────────────────────────────────────────────────────
نکتهٔ مهم دربارهٔ امضا
──────────────────────────────────────────────────────────────────────────────
۴ فایل APK فعلی با همان beevpn-release.jks تحویلی امضا شده‌اند. تا وقتی همان
keystore را در Secrets بگذارید، بیلدهای بعدی CI روی همین نصب‌ها به‌صورت
آپدیت نصب می‌شوند؛ اگر keystore عوض شود، کاربر باید برنامه را حذف و دوباره
نصب کند.
